## What GemFetch is

A Chrome **Manifest V3** extension. One click on the toolbar icon captures the
current page's AI-assistant conversation, cleans it up via the **Gemini API using
the user's own key**, and saves it as a Markdown file into a **subfolder of the
user's Downloads folder**. The user reviews an editable title + bullet synthesis
before saving (or turns on auto-save for zero-touch).

- Repo: `github.com/alematic/GemFetch` (remote `origin`, branch `main`).
- Author: Alessandro Fulciniti (GitHub `alematic`, PayPal `afulciniti95`).
- License: MIT. Not affiliated with Google.
- Landing page + privacy policy: `docs/` → GitHub Pages at
  `https://alematic.github.io/GemFetch/`.
- Not yet on the Chrome Web Store. `STORE_LISTING.md` holds the draft + checklist.
  Dev account registration ($5) is paid.

No build step, no framework, no dependencies, no bundler. Plain ES loaded as
`<script>` tags (popup/options) or `importScripts` (service worker).

## Files

| File | Role |
|---|---|
| `manifest.json` | MV3. Permissions: `activeTab`, `scripting`, `storage`, `tabs`, `tabGroups`, `downloads`. Host permission: `generativelanguage.googleapis.com` only. Has a `background.service_worker`. **Bump `version` on every Web Store upload.** |
| `shared.js` | Core with **no DOM / no `window`**. Loaded by `popup.html`, `options.html`, and `background.js` (via `importScripts`). Contains: `discoverModels`, `suggestedReplacement`, `slug`, `datePrefix`, `safeSegment`, the Gemini `PROMPT`, `synthesize`, `summarizeWithFallback`, `buildMarkdown`. |
| `scrape.js` | A single self-contained function `scrapeConversation()` injected into the active tab via `chrome.scripting.executeScript({func})`. Must not reference anything outside itself. Walks the DOM → Markdown. Has a site registry (ChatGPT, Claude, Gemini, Perplexity, Copilot, Grok, Poe, Le Chat, DeepSeek, You.com), Google AI Mode / AI Overview branches, and a generic `<main>`/`<article>` fallback. A text selection > 40 chars always wins. Returns `{ url, query, mode, markdown, sources[], images[] }`. |
| `background.js` | Service worker. Runs the slow work (Gemini call + file download) so it **survives the popup closing**. Job state lives in `chrome.storage.local.job`. Keep-alive `setInterval` while a job runs. Owns `downloadMarkdown` + the `downloads.onDeterminingFilename` listener. |
| `popup.js` / `popup.html` | Toolbar popup. Kicks off a job, shows progress, lets the user edit title/synthesis and Save, lists recent saves. Driven by `chrome.storage.onChanged` on the `job` key. UI-only — imports nothing from `shared.js` (it's still loaded but unused; harmless). |
| `options.js` / `options.html` | Settings: API key, model (+ Refresh to re-discover), Save folder (Downloads subfolder), auto-save, tab-group foldering, group/archive names, extra prompt instructions. |
| `icons/` | `icon{16,32,48,128}.png` — white gem on a blue gradient rounded square, generated by a dependency-free Node script (not kept in-repo; see history if it needs regenerating). |
| `docs/` | `index.html` (landing page, PayPal donate) + `privacy.html`, for GitHub Pages. |
| `README.md`, `PRIVACY.md`, `STORE_LISTING.md`, `LICENSE` | Docs + Web Store submission draft/checklist. |

## Data flow

```
toolbar click → popup.js
  → chrome.scripting.executeScript({ func: scrapeConversation })   (in popup, uses activeTab)
  → { markdown, query, mode, sources, images }
  → chrome.runtime.sendMessage({ type:"summarize", scrapeData, group, tabId })
background.js runSummarize:
  → storage.local.job = { phase:"running", scrapeData, ... }       (popup observes via storage.onChanged)
  → summarizeWithFallback(cfg, scrapeData, signal)
      → synthesize() → Gemini generateContent → PLAIN TEXT:
        "TITLE: …\nSYNTHESIS:\n- …\nCONVERSATION:\n### Prompt 1 …"  (parsed by regex, NOT JSON)
      → on HTTP 404 "model retired": switch to suggested/other model, persist, retry once
      → on HTTP 429: wait (honouring retryDelay, capped) and retry once
  → if autoSave: writeFile() now;  else: job.phase = "ready"  (popup shows editor)
popup Save → sendMessage({ type:"save", title, synthesis, group })
  → background writeFile():
      buildMarkdown() → downloadMarkdown(relPath, md)
        → Blob URL (data: URL fallback) + chrome.downloads.download
        → downloads.onDeterminingFilename forces relPath   (see gotcha below)
      → job.phase = "saved", savedAs, downloadId
      → recent[] unshifted (keeps the md text so "→ Archive" can re-file)
```

`job.phase`: `running` → `ready` → `saved`; or `cancelled` / `error`. Popup only
*resumes* a `running`/`ready` job for the current tab on open; other phases start
a fresh job.

Output file: `<Downloads>/<saveFolder>/[<group>/]YYMMDD-<title-slug>.md` with
YAML front-matter (`title, source, group?, query, saved`), an `[↗ Open this chat]`
link, `## Synthesis`, `## Conversation` (numbered `### Prompt N` / `### Response N`),
then `## Images` (prompt + answer images not already inline) and `## Sources`.

## Hard constraints — do not break these

- **No backend, ever.** No analytics, telemetry, remote code. The only network
  call is to Gemini with the user's key. Core privacy promise in `PRIVACY.md`,
  `docs/`, `STORE_LISTING.md`.
- **`scrape.js`'s function must stay self-contained** — it is stringified and
  injected; any closure over outer scope throws in the page.
- **`shared.js` must stay DOM-free** — it runs in the service worker.
- **Saving goes through `chrome.downloads` only.** Do NOT reintroduce the File
  System Access API — it was removed in v2.0.0 because it re-prompted for folder
  permission every browser session and could not be driven from the worker.
  Consequence: files can only be written under `~/Downloads/`.
- Secrets (API key, settings, recent notes incl. their Markdown) live only in
  `chrome.storage.local`. `.gitignore` blocks `*.local` and `secrets.*`.
- The service worker can be killed any time; nothing may rely on SW in-memory
  state surviving. `PENDING_DL` and `ABORT` are best-effort within one job.

## Gotchas learned the hard way

- **Gemini + JSON = broken.** Asking for the transcript inside a JSON string fails
  constantly — Gemini mis-escapes `"`, `\`, newlines, ``` fences → "Unterminated
  string in JSON". `synthesize()` uses a plain `TITLE:/SYNTHESIS:/CONVERSATION:`
  delimited format parsed with regex. Keep it that way. Truncated output still
  yields a usable title + synthesis + partial transcript.
- **`chrome.downloads` + blob/data URL ignores the `filename` option** → files
  saved as `download.md`. Fixed by `downloads.onDeterminingFilename` in
  `background.js`, matching our own downloads by URL and calling
  `suggest({ filename, conflictAction:"uniquify" })`. The listener is wrapped in
  try/catch in case the event is unavailable.
- **File System Access `requestPermission` needs a user gesture** — this is one
  reason the FSA API was abandoned. (Historical; no longer relevant.)
- **Model names rot.** Google retires model ids for new keys every few months
  (`gemini-2.5-pro`, `-2.5-flash`, `-2.0-flash` were all retired during
  development). Never hardcode. `discoverModels()` lists what the key can use;
  `summarizeWithFallback()` auto-switches on a 404, reading Google's suggested
  replacement from the error body (`use models/X`).
- **Free-tier quota (429)** is per-model per-day/minute. "flash" models have the
  most generous free allowance. A consumer Gemini subscription does NOT raise API
  limits — only Cloud billing on the key's project does.
- **Google AI Mode URLs carry a session token** (`vsrid=`, `gsessionid=`) and
  don't reliably reopen the exact conversation. ChatGPT/Claude/Gemini/Perplexity
  URLs are stable. Nothing we can fix.
- **Chat-site markup shifts constantly.** Per-site capture is intentionally just
  "find the right root, dump `<main>` to Markdown, let Gemini clean it" rather
  than fragile per-turn selectors. The selection fallback is the escape hatch.
- **Stale extension errors**: after a big refactor, `chrome://extensions` keeps
  old errors (e.g. `idbGet is not defined` from a pre-v2 build). Clear them and
  reload before trusting the error list.

## Working conventions

- 2-space indent, double quotes, semicolons, small focused helpers, terse
  `// ---- section ----` banners. No formatter/linter configured; keep diffs
  minimal and in-style.
- After changing extension code the user must reload at `chrome://extensions`
  (a service-worker change needs a full card reload; then reopen the popup).
- `node -c <file>.js` on every JS file before committing; `node -e "JSON.parse(...)"`
  on `manifest.json`.
- Commit messages: `vX.Y.Z — summary` for releases, plain imperative otherwise.
  Bump `manifest.json` `version` with any user-facing change. End commit messages
  with `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`.
- Do **not** commit or push unless asked. When asked, the user's git identity is
  `alematic` / `fulcinitialessandro@gmail.com` (pass with `-c user.name=… -c user.email=…`).
- Line endings: repo is LF; the Windows checkout warns CRLF on every file. If this
  ever needs addressing, add `.gitattributes` (`* text=auto eol=lf`) rather than
  hand-fixing.
- Shell here is PowerShell for the user; the Bash tool works for POSIX scripts.
  `gh` is NOT installed — repo/remote operations are done via the GitHub website.

## Settings keys (`chrome.storage.local`)

`apiKey`, `model`, `modelList[]`, `customPrompt`, `downloadDir` (default `GemFetch`),
`autoSave` (bool), `useGroups` (bool), `defaultGroup` (default `Inbox`),
`archiveGroup` (default `Archive`), `recent[]` (last 12, each with `md` text),
`job` (current/last job state).
